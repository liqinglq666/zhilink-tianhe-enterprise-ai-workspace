# 合同本地规则预检

合同模块现在采用“两阶段”处理：

1. 服务端读取 `data/contract_risk_rules.json`，执行确定性的关键词与高风险表述扫描。
2. 将扫描结果和合同原文一起交给模型复核，生成商务风险提示报告。

## 输出边界

本地扫描会输出：

- 稳定规则编号，例如 `CR-PAYMENT`、`CR-DATA`
- 命中关键词
- 从用户合同文本中截取的短证据片段
- 本地风险等级
- 规则建议动作
- 待人工确认问题

本地扫描不会：

- 判断合同是否合法或有效
- 断言未命中的条款一定缺失
- 替代律师、法务或其他专业人员复核
- 修改用户输入的合同文本

最终结果末尾的“本地规则预检明细”由服务端确定性生成，不依赖模型自由发挥。模型负责结合完整上下文复核、解释和提出修改建议。

## 规则字段

每条规则包含：

```json
{
  "id": "CR-PAYMENT",
  "name": "付款与结算风险",
  "severity": "中",
  "keywords": ["付款", "结算"],
  "high_risk_patterns": ["以后续通知为准"],
  "advice": "建议明确金额和付款节点。",
  "confirm_questions": ["付款金额和时间节点是否固定？"]
}
```

要求：

- `id` 必须唯一且保持稳定，避免报告和测试失去可追踪性。
- `severity` 只允许 `高`、`中`、`低`。
- `keywords` 用于定位风险类别，不应包含过于宽泛的单字。
- `high_risk_patterns` 只在同一命中证据片段内提升本地预警等级，不能单独作为最终法律判断。
- `confirm_questions` 应写成用户或审核人员可以直接核对的问题。

## 当前规则类别

- `CR-PAYMENT`：付款与结算
- `CR-DELIVERY`：交付与验收
- `CR-BREACH`：违约与解除
- `CR-IP`：知识产权
- `CR-DATA`：数据安全与保密
- `CR-SCOPE`：合作范围与变更

## 测试

```bash
pytest -q tests/test_contract_rules.py
```

测试覆盖规则编号唯一性、高风险表述升级、证据长度限制、无关表述不得错误升级风险、未命中类别的谨慎表达，以及普通/流式 Agent 接入。
