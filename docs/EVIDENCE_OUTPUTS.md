# AI 输出证据与待确认字段

除合同模块外，企业档案、会议纪要、政策准备、供需协作、实施计划和综合报告现在统一使用“服务端证据索引 + AI 分析 + 确定性附录”的输出方式。

合同模块继续使用更严格的本地风险规则预检，详见 `docs/CONTRACT_RULES.md`。

## 输出流程

```text
用户输入或既有模块结果
→ 服务端建立稳定证据编号
→ 将证据索引和待确认项传给模型
→ 模型引用证据编号生成分析
→ 服务端追加确定性的“输入证据与待确认索引”
```

模型无法删除或改写最终附录中的证据编号、输入摘录和系统识别的待确认问题。

## 三类信息必须分开

### 输入事实

来自用户表单、会议原文、企业档案、落地配置或已有模块结果。

示例：

```text
[MT-01] 会议决定由运营组负责总协调。
```

### AI 推断

对输入事实进行解释、排序、预测、风险分析或给出建议。

示例：

```text
AI 推断：运营组可能成为当前项目的主要进度瓶颈。
```

AI 推断不能写成已经确认的业务事实。

### 待确认信息

输入中缺少、表述模糊或会影响结论的信息。

示例：

```text
[MT-C01] 请确认待办事项的具体截止时间。
```

负责人、日期、金额、数量、责任主体、政策名称和成效指标没有证据时，必须进入待确认字段。

## 证据编号

不同模块使用独立前缀：

| 前缀 | 模块或来源 |
|---|---|
| `PF` | 企业档案输入 |
| `MT` / `MP` | 会议原文 / 企业档案上下文 |
| `PL` / `PD` / `PR` | 政策企业信息 / 政策需求 / 本地方向库 |
| `MF` / `MO` / `MN` / `MT` / `MS` | 供需协作输入 |
| `LF` / `LC` / `LR` | 实施计划企业信息 / 配置 / 既有结果 |
| `RP` | 综合报告的模块结果 |

带 `C` 的编号表示待确认项，例如 `MT-C01`。

## 政策模块特殊边界

`PR-*` 表示本地政策方向库参考，不是实时政策检索结果，也不是官方政策来源。

正式使用前必须核对：

- 政策全称
- 发布部门
- 官方链接
- 发布日期
- 有效期
- 适用区域
- 申报条件
- 申报时间窗口
- 官方材料原文

在第三阶段接入真实政策检索以前，系统不得生成未经输入提供的政策文号、资助金额、申报截止日期或成功承诺。

## 确定性附录

每份非合同 AI 结果末尾都会追加：

```text
## 输入证据与待确认索引
```

其中包括：

- 证据编号
- 来源类型
- 来源位置
- 字段名称
- 有长度限制的输入摘录
- 系统识别的待确认问题

证据摘录只证明输入中出现过相关文字，不证明内容真实、完整、有效或已经获得批准。
